# Phase 1 demo account and access
- Signed-out V2 working URLs redirect to login. Master Admin enters the working demo; other active employees enter a read-only access preview. No credentials or real authentication. Invited/inactive employees cannot sign in.
- The demo session is separate from shared records and persists across tabs/reloads. Logout clears only the session key. Master Admin workspace requires an active master-role assignment at an active company and branch, then intentionally allows all fictional business operations. This is not the production grant matrix; the profile separately displays assigned grants.
- The access preview uses saved users, roles, pages, actions, assigned active locations and example record relationships. Grants do not cross branches; deferred pages remain deferred. Sensitive actions can require further evidence or policy. No business actions are performed by the preview.
- Public static code and browser storage are inspectable. No operational staff workspaces, server security, real audit, or Phase 3 policies. Reports/activity are demos, exports are planned.
- No business data migration, reset, or V1 changes.
- Manual checks: Master Admin sign-in, profile, logout, order persistence, invited account denied, salesperson branch/access preview, direct working URL redirect, return to Master Admin.
